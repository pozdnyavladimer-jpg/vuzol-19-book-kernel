## 0. Що досліджує ця серія

Це послідовний набір спроб перевести Квітку з образу у **перевірювану та спростовувану модель**: фізичні стани, пам’ять матеріалів, хвильові режими, відносні координати, ребра взаємодії, залежності знань, локальне виправлення помилок та прогноз переходів.

```text
форма → топологія → матеріальна пам'ять → перекриття режимів
      → хвильовий алфавіт → Gate/Unwind → dependency memory
      → відносна система відліку → локальні зв'язки / transport
      → фазові дефекти → перевірка здатності прогнозувати
      → реакційний граф / learned resonance memory
      → [240] стабільний обмін → новий функціональний вузол
```

**Провідний принцип перевірки:** не оголошувати «Квітку» універсальною фізичною геометрією; порівнювати з контрольними графами, відокремлювати згенеровані синтетичні дані від експериментальної природи, а красиву аналогію — від математичного чи причинного доказу.

## 3. Головні переломні моменти досліджень

1. **217–219:** пам’ять міститься не лише в топологічному циклі — важливі матеріальні змінні та історія.
2. **220–222:** у сліпих тестах не підтвердилися заздалегідь вибрані константи перекриття чи число октав.
3. **223–227:** головною стає операційна граматика `Gate / Commit / Unwind / Rewrite`, а не лише символи `+` і `−`.
4. **228A–231:** від фіксованих частот перейшли до відносних описів і пошуку опорного режиму.
5. **232–233:** інваріантність і локальний перенос стали явними математичними конструкціями, які можна перевіряти негативними контролями.
6. **234:** у синтетичному інтерференційному полі природно для цієї постановки виникли фазові winding-дефекти.
7. **235–236:** наявність дефекту та слабкий спектральний gap не дали потрібного надійного випереджального прогнозу.
8. **238–239:** табличні результати переводять тему до rollback хімічних залежностей і навчених відносних станів пам’яті.
9. **240 (план):** чи може багаторазово перевірений обмін між раніше окремими системами утворити стійкий макровузол з новою функцією?

### Поточна робоча гіпотеза

```text
observable state + model memory
    ↓
predicted transition
    ↓
SHADOW = mismatch / unresolved consequence
    ↓
relevant edges → falsifier / Gate
    ↓
selective REPAIR / HOLD / BLOCK / COMMIT
    ↓
MemoryAtom / ShadowAtom
    ↓
revised transition model
```

*Гіпотеза:* значуща Тінь може вказувати на відмову поточної моделі переходу. **Не доведено**, що один скаляр залишку або одна геометрична ознака універсально передбачає фазову чи топологічну перебудову.

## 5. Порівняння, обмеження, наступні експерименти

### ALLOW — що підтримують конкретні тести

- У заданих синтетичних DAG selective repair правильно перебудовував уражені залежності без повного скидання.
- Історично залежні стани можуть зберігати пам'ять без обов'язкової топологічної петлі.
- Відносні ознаки можуть переноситися між модельними геометріями краще, ніж абсолютні, за умов їхніх генераторів.
- Явно задані групові перетворення дозволяють тестувати інваріантність.
- У синтетичному комплексному полі можуть виникати winding-дефекти біля малої амплітуди.

### HOLD — що ще потребує перевірки

- Чи Квітка насправді перевершує інші графи за зіставних обчислювальних ресурсів.
- Чи прогнозна Тінь з’являється **раніше** від реальних переходів на незалежних даних.
- Чи стабільне ребро можна без втрати істотних наслідків згорнути в функціональний макровузол.
- Чи 3/6/9 та 7×6 є оптимальними розбиттями, а не корисною інженерною домовленістю.
- Чи можна узгодити фізичну пам’ять, пам’ять графа і професійний Gate в одному benchmark.

### BLOCK — які сильні твердження не підтримані

- «Кожне кільце автоматично є пам’яттю».
- «Геометричне перекриття Квітки має універсальну оптимальну константу».
- «Фазові дефекти самі по собі передбачають наступну форму».
- «Мала щілина між двома провідними модами завжди відкриває Gate».
- «Синтетична локальна gauge-аналогія доводить нове фундаментальне поле».

### Запропонований тест №240

Порівняти звичайне інкрементальне оновлення графа з моделлю, яка:

1. ідентифікує релевантні Shadow-ребра;
2. перевіряє повторюваний обмін і його наслідки;
3. зберігає структурну пам’ять;
4. створює кандидатний макровузол зі **збереженням можливості розгортання й аудиту**;
5. проходить на контрольних топологіях, пошкоджених ребрах і змінах середовища.

Показники: correctness, predictive utility, compute time, recomputed nodes, memory overhead, false-green, recovery, generalization; потрібні held-out тести та контроль з випадковими графами.
