# 06 — Відтворення

[План читання](README.md)

## Вимоги

Python 3.10+, стандартна бібліотека. Доступ до мережі, API та LLM не потрібний. Команди нижче виконуються з кореня `sri-transition-lab`.

```bash
python tools/check_package.py
python tools/reproduce.py --suite synthesis
python tools/reproduce.py --suite triangles
python tools/reproduce.py --suite memory
python tools/reproduce.py --suite applications
```

Усі набори разом:

```bash
python tools/reproduce.py --suite all
```

## Що робить reproduce.py

1. Перевіряє SHA-256 включених кодових файлів і початкових свідчень.
2. Копіює потрібний експеримент у тимчасовий каталог.
3. Виконує його з тим самим маніфестом і початковими даними.
4. Порівнює JSON із включеним результатом, виключивши явно задокументовані нестабільні поля.
5. Записує новий підсумок у `verification/REPRODUCIBILITY.json`.

Ігноруються лише час у наносекундах/мілісекундах і діагностичні розміри `repr` пам’яті, залежні від порядку Python-множин. Кількості задач, статуси, маршрути, свідчення, ін’єкції та детерміновані лічильники повинні збігтися.

`check_package.py` перевіряє цілісність свідчень, локальні Markdown-посилання, закриття блоків і збалансованість фігурних дужок у формулах. Це статична перевірка, не емуляція GitHub MathJax/Mermaid.

## Чому є готові результати

Вони дозволяють читачеві перевірити, що саме стоїть за таблицями. Код експериментів скопійовано без змін; його контрольні суми збігаються з початковими маніфестами. Файл [FILE_HASHES.json](evidence/FILE_HASHES.json) пов’язує кожен файл із вихідним експериментом.

Не запускай `prepare` поверх архівного маніфесту, якщо мета — відтворити старий результат. Для нового досліду спершу зроби окрему копію експерименту, зміни код або дані, потім сформуй новий маніфест і окремий звіт.

## Власні перевірки

Змінюй одну умову за раз: дані, версію правила, бюджет, тип гарантії, параметр k або розподіл DNF. До запуску запиши очікування й критерії. Перевіряй також правильні випадки, щоб не отримати аудитор, який просто блокує все.
