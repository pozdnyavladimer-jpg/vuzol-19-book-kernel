# 03 — Активна пам’ять, гелікс і октави

## Від журналу до керування пошуком

```math
M_{t+1}=\operatorname{Append}(M_t,X_t,O_t,V_t,\mathrm{evidence}_t).
```

Самого запису недостатньо. Eligible або Select повинні читати M та змінювати наступний пошук. У виконаному досліді несумісна трійка множин виключає всі наступні кандидати, що її містять, у чинному контексті перевірки.

| Шар | Що повторно використовує |
|---|---|
| Журнал | Історію для читання й аудиту |
| Точний кеш | Результат для того самого входу, параметрів і версій |
| Активна пам’ять | Контрприклади, обмеження й перевірені структурні правила |
| Макроконтракт | Композицію операцій разом із передумовами й доказом стику |

DNA-like route / helix позначає впорядковану історію змін орієнтації та стану. Спіральна картинка сама не доводить, що пам’ять впливає на вибір.

## Структура запису

Це схема для майбутнього спільного runtime; наявні експерименти мають окремі простіші формати.

```json
{
  "schema_version": "0.1",
  "transition_id": "task17-v2",
  "parent_id": "task17-v1",
  "intent_id": "exact_target_function",
  "input_version": 1,
  "rule_version": 1,
  "domain": "rational_numbers",
  "preconditions": ["x != -1"],
  "operation": "guarded_reciprocal_route",
  "preserved": ["target_value", "required_domain"],
  "decision": "ALLOW",
  "decision_scope": "all rational x except -1",
  "evidence_status": "CURRENT",
  "evidence": ["polynomial_identity", "exception_branch_check"],
  "dependencies": ["inv_contract_v1", "target_spec_v1"],
  "unresolved": [],
  "external_action_authorized": false
}
```

CURRENT і STALE характеризують чинність свідчення; це не заміна ALLOW/HOLD/BLOCK. Застарілий дозвіл потребує переоцінки. Інвалідація поширюється на залежні результати; незалежні записи не потрібно знищувати, якщо межа впливу відома.

## Композиція

```math
T_{\mathrm{macro}}=T_n\circ\cdots\circ T_1.
```

```math
\operatorname{Post}_{T_i}(s)\Rightarrow
\operatorname{Pre}_{T_{i+1}}(s).
```

Додатково потрібно зберегти інваріанти цілої задачі, врахувати побічні ефекти та залежності, забезпечити завершення в заявленому режимі. Два ALLOW для окремих числових входів не доводять загального макроконтракту.

Сумісність може бути правильною лише на вужчій області. Тоді макрос зберігає цю область, а не оголошується універсальним.

## Вартість октави

Один макровиклик може приховувати багато операцій. Згорнутий маршрут не доводить O(1) виконання. Треба врахувати:

- пошук і побудову макросу;
- доведення та перевірку передумов;
- витрати виконання;
- пам’ять, підтримку версій та повторний аудит.

Трикутне кодування також не гарантує стиснення. У виконаному досліді деякі серіалізовані DAG були більші за прямий список чисел.
