# 40_FUTURE_INTENT_BOOK_PROTOCOL.md
# Вузол-19 — Future Intent Book Protocol v0.1

> **Цей файл фіксує головну людську функцію книги “Вузол-19”.**  
> Книга не має бути просто фантастикою про майбутнє.  
> Вона має стати **капсулою наміру**: внутрішнім механізмом для людини, яка зараз не бачить майбутнього, але може зробити одну маленьку перевірку в реальності.

---

## 1. Одне речення

**Future Intent Book Protocol — це правило, за яким роман дає читачу не готове майбутнє, а спосіб перевіряти майбутнє маленькими діями, що проходять через тінь, Квітку, Human Gate і Memory Update.**

Коротко:

```text
reader pressure
→ shadow recognition
→ Flower scan
→ small real test
→ Human Gate
→ tiny commit
→ memory update
→ next possible future
```

Головна фраза:

> **Майбутнє не треба чекати.  
> Його треба перевіряти.**

---

## 2. Для кого ця книга

Книга має бути не тільки для “сильних”, “успішних” або тих, хто вже має напрям.

Вона особливо потрібна тим, хто:

```yaml
TARGET_READER:
  states:
    - "лежить і не має сил"
    - "застряг у телефоні"
    - "втратив напрям"
    - "живе в соромі"
    - "має залежність"
    - "не бачить себе в майбутньому"
    - "думає, що вже запізно"
    - "хоче, щоб хтось вибрав за нього"
    - "має фантазію, але не має маршруту"
```

Але книга не має казати:

```text
ти слабкий
ти зламаний
ти неправильний
ти непотрібний
```

Вона має казати:

> **Ти не бачиш майбутнє не тому, що його нема.  
> Твоя система зараз у HOLD.**

## 6. Малий commit

Книга не має вимагати великої трансформації одразу.

Вона має показати силу маленької дії.

```yaml
SMALL_COMMIT_EXAMPLES:
  instead_of_change_everything:
    do: "сьогодні зроблю один файл"

  instead_of_heal_forever:
    do: "сьогодні не піду у старий цикл на 10 хвилин"

  instead_of_become_genius:
    do: "перевірю одну ідею на фактах"

  instead_of_save_world:
    do: "зберу один вузол"

  instead_of_find_life_path:
    do: "знайду одну дію, яка не краде мій Gate"
```

Фраза:

> **Велике майбутнє починається не з великої віри.  
> Воно починається з малої дії, яка не збрехала.**

## 7. Герой книги

Герой не має бути ідеальним.

Він має проходити стани, які читач впізнає:

```yaml
HERO_RECOGNIZABLE_STATES:
  - "лежання"
  - "сором"
  - "злість"
  - "втеча у фантазію"
  - "залежність від швидкої нагороди"
  - "страх майбутнього"
  - "бажання, щоб хтось вибрав за нього"
  - "доведення себе"
  - "false-green спокій"
  - "старий attractor"
```

Але книга показує:

> **Проблема не в тому, що людина непотрібна.  
> Проблема в тому, що її намір не має маршруту.**

Головний закон героя:

```text
намір без маршруту стає болем
намір з маршрутом стає майбутнім
```

## 8. Роль капсули, окулярів, коробки, корони, AI і Квітки

```yaml
FUTURE_INTENT_SYSTEM:

    role: "показують маленький шлях назад"
    danger: "можуть стати навігацією без вибору, якщо крадуть Gate"

  box_phone:
    role: "памʼятає повтор тіні"
    danger: "може зробити prediction-prison"

  crown:
    role: "читає поточний стан"
    danger: "може бути використана як контроль без consent"

  ai_guard:
    role: "каже: це не ти, це старий цикл"
    danger: "може вирішити за людину, якщо забуде Human Gate"

  flower:
    role: "дає HOLD або малий commit"
    danger: "може стати догмою, якщо Human Gate підмінений"

    role: "людина вибирає сама"
    danger: "якщо його вкрали, майбутнє стає пасткою"
```

Коротко:

```text
капсула показує світ
окуляри тримають return path
коробка памʼятає тінь
корона читає стан
AI Guard не дає false-green
Квітка перевіряє
але шлях вибирає людина
```

## 9. Чого книга не має робити

```yaml
FORBIDDEN_BOOK_PATTERNS:
  - "романтизувати залежність"
  - "романтизувати лежання як святість"
  - "казати, що біль робить людину автоматично глибшою"
  - "давати фантазію замість return path"
  - "казати, що AI знає краще"
  - "показувати капсулу як абсолютний рай"
  - "показувати майбутнє як готову відповідь"
  - "змушувати героя швидко зцілитися"
  - "викидати людину, яка зараз у HOLD"
```

Фраза:

> **Не “ти герой, бо страждаєш”.  
> А “ти ще маєш Gate, навіть якщо зараз лежиш”.**

## 10. Як сцена має впливати на читача

Кожна сильна сцена має залишати читачу не тільки емоцію, а маленький внутрішній інструмент.

```yaml
SCENE_READER_EFFECT:
  before_scene:
    reader_state: "я не знаю, що робити"

  during_scene:
    reader_recognizes:
      - "у мене теж є цей тиск"
      - "я теж тікаю в цей цикл"
      - "я теж хочу готову відповідь"

  after_scene:
    reader_gets:
      - "назву для тіні"
      - "малий HOLD"
      - "один можливий commit"
      - "право не знати"
      - "ідею перевірки в реальності"
```

Фраза:

> **Сцена має бути не тільки красивою.  
> Вона має залишити читачу спосіб не збрехати собі завтра.**

## 12. Як це писати в романі

Погано:

```text
Він зрозумів, що майбутнє треба створювати самому.
```

Добре:

```text
Він не встав.

Ще ні.

Тільки відкрив порожній файл.

Назвав його:

first_node.md

І десять хвилин дивився на білий екран.

Потім написав один рядок:

я ще не знаю, але можу перевірити.
```

Погано:

```text
Капсула дала йому нове життя.
```

Добре:

```text
Капсула показала йому три життя.

У кожному він був сильнішим.

У кожному ті самі двері лишались зачинені.

Окуляри тихо підсвітили четвертий варіант:

RETURN_TO_ZERO:
  call your brother
  duration: 2 minutes
  no explanation required
```

Погано:

```text
AI сказав йому правильний шлях.
```

Добре:

```text
AI не дав маршруту.

Він тільки прибрав три красиві брехні.

Після цього лишилась одна маленька дія, яку Володимир не міг списати на систему.
```

## 15. Short prompt for AI

```text
Use Future Intent Book Protocol.

When writing any chapter, do not only advance the plot.
Give the reader a small internal mechanism.

Show:
- pressure without humiliation
- shadow without romanticizing it
- fantasy without letting it become escape
- a return path
- one small real action
- Human Gate
- memory update

The book should not give a ready future.
It should teach the reader to test the future with small commits.

Do not write false hope.
Do not resolve pain too fast.
Do not let AI, capsule, crown, box, pyramid or Flower choose instead of the person.

The strongest scene leaves the reader thinking:
I do not know everything,
but I can test one node.
```
