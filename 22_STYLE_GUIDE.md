# 22_STYLE_GUIDE.md
# Вузол-19 — Style Guide v0.1

> **Цей файл фіксує мову роману “Вузол-19”.**  
> Стиль має бути не туманом, а нервом: короткий кадр, тіло, лог, тінь, Human Gate, наслідок.  
> Технологія говорить сухо. Людина говорить просто. Квітка не пояснює — вона перевіряє.

---

## 1. Одне речення

**Стиль “Вузла-19” — це поєднання живої української прози, коротких runtime-логів, тілесних сигналів, тиші перед дією і точних символів у момент вибору.**

Коротко:

```text
кадр
→ тіло
→ лог
→ тінь
→ пауза
→ дія / блок
→ памʼять
```

Головна фраза:

> **Стиль має не прикрашати систему.  
> Стиль має не дати системі збрехати красиво.**

## 2. Базовий тон

```yaml
STYLE_TONE:
  primary:
    - "тихий"
    - "точний"
    - "напружений"
    - "людяний"
    - "не пафосний"
    - "не містичний туман"
    - "не сухий технічний manual"

  allowed_flavor:
    - "поетичність у фінальній фразі"
    - "короткі технічні логи"
    - "міфоінженерні формули"
    - "психологічна напруга"
    - "побутова простота"
```

## 3. Головний ритм абзацу

Добрий ритм:

```text
1 короткий кадр.
1 тілесний сигнал.
1 лог або знак.
1 людська фраза.
1 наслідок.
```

Приклад:

```text
Піраміда світилася рівно.

CITY_GRID: STABLE

Пес біля білої лінії сів.

Володимир відчув, як на секунду зупинилось дихання.

△

Піраміда не змінила кольору.

Саме це було неправильно.
```

## 4. Довжина речень

```yaml
SENTENCE_LENGTH:
  short:
    use_for:
      - "удар"
      - "блок"
      - "страх"
      - "рішення"
      - "фінальна фраза"

  medium:
    use_for:
      - "опис кадру"
      - "внутрішній стан"
      - "рух через простір"

  long:
    use_rarely_for:
      - "плавний опис"
      - "переходи між шарами"
      - "космічний або історичний масштаб"
```

Правило:

> **Коли сцена наближається до дії — речення мають коротшати.**

---

## 5. Мова тіла перед поясненням

Завжди спочатку тіло, потім пояснення.

Погано:

```text
Він відчув сором, бо студентська помилка активувала його тінь.
```

Добре:

```text
Він усміхнувся занадто швидко.

Пальці зібралися в кулак.

Тільки після цього система написала:

shame
```

Правило:

```text
body first
meaning second
audit third
```

## 6. Runtime logs

Логи мають бути короткі й холодні.

```yaml
LOG_STYLE:
  language: "mostly English / system format"
  length: "1-5 lines"
  use_when:
    - "система читає стан"
    - "дія майже стала commit"
    - "Guard блокує"
    - "false-green видно тільки системі"
    - "Memory Update після сцени"

  avoid:
    - "довгі технічні пояснення"
    - "логи в кожному абзаці"
    - "лог без наслідку"
```

Приклади:

```text
CITY_GRID: STABLE
```

```yaml
BODY_SIGNAL:
  breath_hold: true
  chest_pressure: rising
  public_status: GREEN
  private_status: DISAGREEMENT
```

```text
DRIFT_STATE: NOT_A_BOAT_YET
```

```text
HUMAN_GATE: preserved
```

## 7. Українська + English runtime

Основна проза — українською.

Runtime-терміни можна залишати англійською, якщо вони є частиною системи:

```text
Human Gate
Bindu
Guard
Memory Ledger
false-green
PRION
return_to_zero
UNKNOWN PRESERVED
COMMIT_BLOCKED
DRIFT_LOCK
```

Правило:

> **Українська дає тіло.  
> English runtime дає холодний системний край.**

Не треба перекладати все механічно.

Погано:

```text
Людські Ворота були збережені у стані повернення до нуля.
```

Добре:

```text
HUMAN_GATE: preserved

Він не мав права вирішити за неї.
```

## 8. Руни

Руни використовуються мало.

```yaml
RUNE_STYLE:
  max_short_scene: "1-3"
  must_be_functional: true
  use_when:
    - "тілесний тиск"
    - "commit candidate"
    - "action blocked"
    - "false-green detected"
    - "Unknown preserved"
    - "clean action allowed"

  do_not_use_when:
    - "просто красиво"
    - "немає вибору"
    - "немає ризику"
    - "символ не змінює сцену"
```

Приклади:

```text
△
```

```text
⊙╳
```

```text
∅✓
```

```text
◇✓
```

## 9. Як писати Квітку

Квітка — це не магічний орнамент.

Погано:

```text
Квітка Життя засяяла божественним світлом і відкрила істину.
```

Добре:

```text
Квітка не дала відповіді.

Вона тільки показала, де намір втратив центр.
```

Правило:

```text
Flower = audit route
not decoration
not religion
not proof
not prophecy
```

---

## 10. Як писати AI

AI не має бути богом.

```yaml
AI_STYLE:
  voice:
    - "точний"
    - "стриманий"
    - "не емоційний"
    - "не всезнаючий"
    - "не вирішує за людину"

  good_lines:
    - "Recommendation blocked."
    - "Unknown preserved."
    - "Human Gate not transferable."
    - "Pattern similarity detected. Verdict not inherited."
```

Погано:

```text
AI зрозумів, що треба робити, і врятував місто.
```

Добре:

```text
AI показав сім маршрутів.

Перші шість були швидші.

Сьомий зберігав Human Gate.

— Ти рекомендуєш сьомий?

RECOMMENDATION_BLOCKED

— Я не маю права рекомендувати. Я можу тільки показати, де твій вибір не буде вкрадений системою.
```

## 11. Як писати технологію

Технологія має мати наслідок.

```yaml
TECH_STYLE:
  good:
    - "технологія читає стан"
    - "технологія помиляється або не бачить"
    - "технологія блокує дію"
    - "технологія відкриває нову відповідальність"

  bad:
    - "технологія просто світиться"
    - "технологія вирішує сюжет"
    - "технологія пояснюється довше, ніж діє"
```

Приклад:

```text
Екзоскелет зупинив праву руку на півдорозі до сфери.

COMMIT_BLOCKED

Він ненавидів цей блок.

Але через секунду зрозумів: якби рука дійшла, дія була б не його.
```

---

## 12. Як писати біль

Біль — це сигнал, не романтика.

Погано:

```text
Біль зробив його чистим і сильним.
```

Добре:

```text
Біль не давав йому сили.

Біль просто не дозволяв збрехати, що межі більше немає.
```

Правило:

```text
pain = boundary signal
not fuel
not punishment
not beauty
```

---

## 13. Як писати тінь

Тінь не треба засуджувати.

Погано:

```text
Він був слабкий, тому втік у капсулу.
```

Добре:

```text
Він не тікав від дитини.

Він тікав від себе, який не знав, що сказати дитині без обладунків героя.
```

Правило:

> **Показати тінь так, щоб читач не відчув зверхності, а впізнав небезпеку.**

---

## 14. Як писати антагоніста

Антагоніст не має бути дурним злом.

```yaml
ANTAGONIST_STYLE:
  must_have:
    - "рана"
    - "логіка"
    - "страх"
    - "тілесна звичка"
    - "часткова правда"

  must_not:
    - "карикатурне зло"
    - "монолог про владу"
    - "зло без причини"
```

Приклад:

```text
Він вирівняв чашку.

Ручка мала дивитися на схід.

Так було легше дихати.

— Я не прибираю свободу, — сказав він. — Я прибираю повторення травми.
```

---

## 15. Як писати дитину

Дитина не має говорити як пророк.

Погано:

```text
Дитина зрозуміла, що система втратила Human Gate.
```

Добре:

```text
— Він там завжди встигає, — сказала вона. — А сюди ні.
```

Правило:

```text
child = simple truth
not exposition
not mystical oracle
```

---

## 16. Як писати космос

Космос використовується тільки у великих сценах.

Погано:

```text
Планети наказали людям воювати.
```

Добре:

```text
MARS / FE: ACTION PRESSURE HIGH

Марс не наказував їм бити.

Він тільки підняв залізо ближче до руки.

Удар робив той, хто не пройшов Guard.
```

Правило:

```text
planet = resource
orbit = rhythm
mayan clock = replay
not fate
```

---

## 17. Як писати Mayan Memory Clock

Календар Майя не пророкує подію.

Погано:

```text
Календар Майя передбачив війну.
```

Добре:

```text
52-YEAR SHADOW MATCH

— Це та сама війна?

— Ні. Та сама тінь.
```

Правило:

```text
Mayan Clock = phase audit / memory replay
not prophecy
not fatalism
```

---

## 18. Як писати фінальні фрази

Фінальна фраза сцени має бути простою й сильною.

Вона не пояснює все.  
Вона залишає відлуння.

Приклади:

```text
Піраміда світилася правильно.

Саме це було неправильно.
```

```text
Сфера не відмовила йому.

Вона просто не дала його тіні стати тілом.
```

```text
Він не вимкнув Сад Повернення.

Він зробив так, щоб слово “повернення” знову мало двері.
```

```text
Календар не сказав, що станеться.

Він спитав, чи світ знову стоїть у місці, де вже збрехав собі.
```

---

## 19. Рівень термінів у сцені

Не перевантажувати сцену термінами.

```yaml
TERM_LIMITS:
  short_scene:
    max_runtime_terms: 2-4

  chapter_scene:
    max_runtime_terms: 5-8

  technical_file:
    many_terms_allowed: true
```

Погано:

```text
Bindu через Human Gate у Flower Runtime перевірив PRION false-green у Mayan Planetary phase.
```

Добре:

```text
BINDU: HOLD

Він не перейшов лінію.
```

---

## 20. Побут проти масштабу

Великий масштаб треба відкривати через побут.

Погано:

```text
Цивілізація входила в новий фазовий replay.
```

Добре:

```text
Дівчинка тримала малюнок біля скла.

На екрані її батько рятував місто.

У коридорі він не чув, як вона кличе.
```

Правило:

> **Починай з чашки, пса, руки, дихання, скла, кнопки.  
> Тільки потім відкривай піраміду, місто, цикл, космос.**

## 25. Good micro-patterns

### Pattern A — log contradicts body

```text
CITY_GRID: STABLE

Пес не перейшов лінію.
```

### Pattern B — phrase blocked

```text
“Ти нічого не розумієш.”

⊙╳

Він видихнув.
```

### Pattern C — machine ready, human not ready

```text
READY

Пальці зібралися в кулак.
```

### Pattern D — comfort hides missing return

```text
GARDEN_STATUS: HEALING

Дитина чекала біля скла третю годину.
```

### Pattern E — cosmic warning, human decision

```text
MARS / FE: ACTION PRESSURE HIGH

Удар робив не Марс.
```

---

## 26. Bad micro-patterns

```yaml
BAD_MICRO_PATTERNS:
  - "руни світилися і все пояснили"
  - "герой одразу зрозумів істину"
  - "AI вирішив замість людей"
  - "космос наказав"
  - "біль зробив його чистим"
  - "капсули зло"
  - "антагоніст просто хоче влади"
```

Перед збереженням сцени перевірити:

## 28. README / kernel style

У `.md` файлах kernel стиль може бути більш технічний:

```yaml
KERNEL_DOC_STYLE:
  allowed:
    - "tables"
    - "yaml blocks"
    - "formulas"
    - "short definitions"
    - "quoted core laws"

  avoid:
    - "надто довгі філософські абзаци"
    - "одна ідея без структури"
    - "туманні формулювання без runtime use"
```

## 29. Short prompt for AI

```text
Write in Vuzol-19 style.

Start with a concrete image.
Show body before explanation.
Use short runtime logs.
Use runes only at choice points.
Do not make Flower decorative.
Do not let AI replace Human Gate.
Do not romanticize pain.
Do not use cosmic layer unless the scene needs phase audit.
End with consequence or memory.
If the scene becomes beautiful fog, rewrite through body signal.
```
