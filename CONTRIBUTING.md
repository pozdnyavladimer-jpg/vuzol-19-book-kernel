# CONTRIBUTING.md
# Contributing to Vuzol-19 Book Kernel

> **Vuzol-19 is an open-source book-kernel and AI runtime.**  
> You can contribute as a writer, verifier, builder, editor, researcher or tester.

Core law:

> **Not every intent has the right to become action.**

Українською:

> **Не кожен намір має право стати дією.**

---

## 1. Ways to contribute

You can contribute in four simple ways:

```text
1. Write a chapter or scene.
2. Verify a theory through FACT / MODEL / FICTION / HOLD.
3. Build an AI runtime / Flower Decision Panel.
4. Add scene seeds, examples, audits or templates.
```

Advanced future paths:

```text
AI Safety / Human Gate
FlowerBench
Interactive Fiction
Disaster Audit
Education / School of Intent
Personal Decision Scanner
```

---

## 3. Contribution types

### 3.1 Chapter / scene contribution

Use:

```text
templates/SCENE_SEED_TEMPLATE.md
templates/PRE_SCENE_RUNTIME_TEMPLATE.md
templates/POST_SCENE_AUDIT_TEMPLATE.md
```

A scene should include:

```text
PRE_SCENE_RUNTIME
SCENE
POST_SCENE_AUDIT
MEMORY_UPDATE
```

Do not submit a scene that:

```text
steals Human Gate
resolves pain too quickly
makes AI final authority
presents MODEL or FICTION as FACT
romanticizes suffering
calls false-green healing
```

---

### 3.2 Theory verification

Use:

```text
templates/THEORY_CHECK_TEMPLATE.md
FACT_MODEL_FICTION.md
```

Every theory must be separated into:

```text
FACT
MODEL
FICTION
HOLD
```

Do not claim:

```text
MODEL = proven fact
FICTION = historical certainty
pattern = destiny
AI audit = human permission
cosmic rhythm = command
```

---

### 3.3 AI runtime / app contribution

Start with:

```text
apps/flower_decision_panel/
```

Minimum output:

```text
pressure
shadow
Human Gate risk
Flower Scan
Nobel modes
Bindu Verdict
smallest real action
memory update
```

The AI must always be able to say:

```text
HOLD
```

---

### 3.4 Scene seed contribution

Use:

```text
scene_seeds/
templates/SCENE_SEED_TEMPLATE.md
```

A good seed has:

```text
one-line scene
pressure
shadow
Human Gate risk
possible Bindu Verdict
memory update candidate
```

## 4. Pull request rules

Before opening a pull request, check:

```yaml
PR_CHECKLIST:
  read_START_HERE: false
  human_gate_protected: false
  fact_model_fiction_clear: false
  flower_scan_present: false
  shadow_named: false
  memory_update_present: false
  no_false_green: false
```

A pull request should explain:

```text
What changed?
Which path does it help?
Writer / Verifier / Builder / Reader / AI Safety / Other
What Human Gate risk was checked?
What should reviewers look for?
```

---

## 5. Style rules

Write clearly.

Prefer:

```text
short sections
structured YAML blocks
plain language
one strong final sentence
clear FACT / MODEL / FICTION / HOLD boundary
```

Avoid:

```text
overclaiming
unearned certainty
decorative mysticism
AI oracle tone
forcing action
making the system more important than the human
```

---

## 6. Language

Contributions may be in:

```text
English
Ukrainian
bilingual English/Ukrainian
```

If possible, keep filenames in English for repository navigation.

---

## 7. Human Gate rule

Every contribution must respect:

> **AI can audit, warn, compare and draft.  
> AI cannot replace human permission.**

If a contribution removes or weakens Human Gate, it should be rejected or rewritten.

---

## 8. Main sentence

> **Contribute one honest route: a scene, a theory check, a runtime tool, or a small action that helps intent pass through the Flower without becoming a beautiful lie.**
