## 1. Why this file exists

Long conversations create many ideas.

If every idea is stored as raw text, the repository becomes heavy.

If nothing is stored, the idea disappears.

Therefore the repository needs a compression mechanism.

```text
raw conversation
→ unstable mass
→ compression
→ green memory
→ index
→ next transition
```

This is the repository version of black-hole dark memory.

## 3. Black-hole analogy

A black hole does not return old form as old form.

It removes unsafe current and preserves compressed memory.

Repository compression does the same.

```text
conversation mass
→ context overload
→ raw text loses direct usefulness
→ stable idea extracted

→ old chaos loses action-current
```

The old discussion does not need to return as a full transcript.

It returns as:


## 6. Unsafe current in a repository

Unsafe current means a raw idea wants to become action too quickly.

In GitHub, unsafe current appears as:

```text
new file without index
new theory without FACT / MODEL / FICTION / HOLD
duplicate file in wrong folder
README update without checking actual files
AI-generated patch without Human Gate
large concept committed before it stabilizes
```

Unsafe current must be removed before commit.

Not by deleting the idea.

By compressing it.

## 7. PRION in repositories

Repository PRION is a pattern that copies confusion.

It can look like:

```text
duplicate canon
unlinked files
beautiful but unclear theory
scene stored as world theory
engineering model stored as fiction only
old README pretending to describe new repo
same concept with different names
AI repair loop creating new drift
```

PRION rule:

> If a file cannot be found, understood, indexed or bounded, it can become repository PRION.

Anti-PRION action:

```text
single source of truth
clear folder role
index update
README pointer
HOLD boundary
delete or move duplicates
```

## 9. Compression protocol

When a chat or repo becomes heavy, run:

```text
1. Stop adding raw theory.
2. Identify the stable idea.
3. Decide folder role.
4. Create one primary file.
5. Remove duplicates or mark them as references.
6. Add to index.
7. Add README pointer if it is a major entry point.
8. Add FACT / MODEL / FICTION / HOLD if needed.
9. Commit with a clear message.
10. Continue from the compressed file, not from raw chat.
```

This is repository surgery.

## 17. README rule

README should not contain every detail.

README is the visible horizon of the repo.

It should show:


README should point to memory.
