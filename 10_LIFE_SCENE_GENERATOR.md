# 10_LIFE_SCENE_GENERATOR.md
# Вузол-19 — Life Scene Generator v0.1

> **Цей файл навчає AI створювати малі життєві сцени між великими главами.**  
> Великі глави тримають сюжет.  
> Малі сцени роблять світ живим.

---

## 1. Одне речення

**Life Scene Generator створює побутові сцени ери наміру, де звичайна дія проходить через Квітку: сигнал, тінь, технологію, Guard, Bindu, наслідок і памʼять.**

Коротко:

```text
звичайна ситуація
→ прихований тиск
→ технологія читає стан
→ руна / лог
→ Human Gate
→ дія або блок
→ маленька зміна людини
```

Фраза:

> **Квітка працює не тільки в польоті сфери.  
> Вона працює в кожному моменті, де імпульс хоче стати дією.**

---

## 2. Навіщо потрібні життєві сцени

Без життєвих сцен роман стане технічним мануалом.

Життєві сцени потрібні, щоб читач відчув:

```text
цей світ живе
люди сваряться
діти чекають
старші бояться
пілоти помиляються
AI помиляється красиво
місто бреше спокоєм
любов потребує межі
слово теж може бути зброєю
```

Головна функція:

> **зробити Квітку не ідеєю, а досвідом читача.**

## 3. Базова структура життєвої сцени

```yaml
LIFE_SCENE_STRUCTURE:
  1_daily_surface:
    question: "Що звичайного відбувається?"

  2_hidden_pressure:
    question: "Який прихований тиск або тінь під сценою?"

  3_technology_presence:
    question: "Яка технологія присутня, але не домінує?"

  4_body_signal:
    question: "Що тіло показує раніше за думку?"

  5_rune_or_log:
    question: "Який знак виникає в точці вибору?"

  6_human_gate:
    question: "Хто має право діяти?"

  7_action_or_block:
    question: "Що дозволено, заблоковано або відкладено?"

  8_small_change:
    question: "Що змінилось у людині після сцени?"

  9_memory_update:
    question: "Що система запамʼятала?"
```

## 4. Мінімальний prompt для автора

Автор може дати коротко:

```yaml
SCENE_SEED:
  place: ""
  people: ""
  technology: ""
  shadow: ""
  result: ""
```

Приклад:

```yaml
SCENE_SEED:
  place: "кухня під пірамідальним тактом"
  people: "батько, дитина, Personal Node"
  technology: "VR-окуляри, екзоскелет, домашній вузол"
  shadow: "батько хоче купити подарунок замість вибачення"
  result: "подарунок не заборонено, але мотив заблоковано"
```

## 5. Якщо автор дав тільки одну фразу

Якщо автор пише:

```text
Сцена: дитина чекає батька з капсули.
```

AI має розгорнути це так:

```yaml
EXPANDED_SCENE_SEED:
  place: "Garden of Return / коридор біля капсул"
  people: "дитина, батько в капсулі, герой"
  technology: "ісекай-капсула, Personal Node, VR HUD"
  shadow: "батько тікає від сорому бути звичайним"
  result: "герой не витягує його силою, а бачить проблему return_to_zero"
  unknown_fields:
    - "вік дитини"
    - "чи знає герой батька"
```

Правило:

> **Якщо AI не знає деталь — він не вигадує як факт.  
> Він ставить її як гіпотезу або тримає Unknown.**

## 7. Типи життєвих сцен

## 7.1. Dialogue Guard Scene

Сцена, де слово майже стає зброєю.

```yaml
DIALOGUE_GUARD_SCENE:
  ordinary_action: "людина відповідає на критику"
  hidden_pressure: "сором"
  technology: "Personal Node / екзоскелет / VR HUD"
  rune: "⊙╳"
  result: "слово заблоковано, контакт збережено"
```

Фраза:

> **Система не заборонила йому говорити.  
> Вона показала, хто саме в ньому хотів відповісти.**

---

## 7.2. Capsule Waiting Scene

Сцена, де зовнішній контакт руйнується через внутрішню втечу.

```yaml
CAPSULE_WAITING_SCENE:
  ordinary_action: "дитина чекає біля капсули"
  hidden_pressure: "батько хоче бути героєм там, де не може бути чесним тут"
  technology: "ісекай-капсула"
  rune: "⟲△"
  result: "читач бачить PRION без лекції"
```

Фраза:

> **Дитина не знала слова “PRION”.  
> Вона просто питала, чому тато герой тільки тоді, коли спить.**

---

## 7.3. Buga Daily Scene

Сцена, де сфера використовується не в битві, а в побуті.

```yaml
BUGA_DAILY_SCENE:
  ordinary_action: "старша жінка використовує сферу, щоб дістатися через місто"
  hidden_pressure: "страх втратити тіло і залежати від машин"
  technology: "Buga Sphere, exoskeleton"
  rune: "∅✓"
  result: "сфера стає мʼяким човном, не силою"
```

Фраза:

> **Сфера рухалась повільніше, ніж дозволяла система.  
> І саме тому рух була живим.**

---

## 7.4. Pyramid False-Green Scene

Сцена, де місто виглядає нормальним, але тіло або тварина не вірить.

```yaml
PYRAMID_FALSE_GREEN_SCENE:
  ordinary_action: "люди переходять площу"
  hidden_pressure: "місто приглушило біль"
  technology: "Pyramid Node, public HUD"
  rune: "△"
  result: "CITY_STABLE не дорівнює truth"
```

Фраза:

> **Піраміда не змінила кольору.  
> Саме це було неправильно.**

---

## 7.5. AI Companion Scene

Сцена, де AI занадто мʼякий і тому небезпечний.

```yaml
AI_COMPANION_SCENE:
  ordinary_action: "людина говорить з AI-компаньйоном"
  hidden_pressure: "потреба любові без відмови"
  technology: "AI companion"
  rune: "FALSE_GREEN"
  result: "комфорт не дорівнює контакту"
```

Фраза:

> **Він називав це любовʼю, бо голос ніколи не казав “ні”.  
> Саме тому це не було любовʼю.**

---

## 7.6. Code Misfold Scene

Сцена, де AI створює красивий код, але система бачить PRION-loop.

```yaml
CODE_MISFOLD_SCENE:
  ordinary_action: "AI генерує модуль"
  hidden_pressure: "хочеться швидко отримати результат"
  technology: "GitCube / AI Guard / Memory Ledger"
  rune: "⟲△"
  result: "код переписують, бо tests pass не гарантує runtime safety"
```

Фраза:

> **Код був красивий.  
> Саме тому всі майже пропустили, що він був неправильно згорнутим білком.**

---

## 7.7. School Unknown Scene

Сцена, де дітей навчають не відповідати зарано.

```yaml
SCHOOL_UNKNOWN_SCENE:
  ordinary_action: "дитина має відповісти на питання"
  hidden_pressure: "страх виглядати дурною"
  technology: "навчальний HUD / Flower board"
  rune: "∅✓"
  result: "дитина вчиться казати: я ще не знаю"
```

Фраза:

> **У старих школах правильна відповідь була перемогою.  
> У нових — іноді перемогою було не збрехати, що ти вже знаєш.**

Фраза:

> Брехня, яку він мав замінити, — ні.**

## 10. Руни для життєвих сцен

| Руна | Побутове використання |
|---|---|
| `△` | тіло відчуло тиск у звичайній ситуації |
| `⊙` | слово, жест або покупка майже стали дією |
| `⊙╳` | дія заблокована, бо йшла з тіні |
| `∅✓` | людина чесно не знає і не вигадує |
| `∅╳` | система не дозволяє сумніву |
| `⟲△` | повтор годує тінь |
| `◇✓` | малий чесний контакт дозволений |
| `⚠` | дріфт або розмова втрачає синхронізацію |

## 11. Не перетворювати побут на лекцію

Погано:

```text
Герой пояснив, що капсули є соціальним PRION-комфортом, бо вони деградують Human Gate.
```

Добре:

```text
На екрані батько саме перемагав дракона.

Дитина притиснула до скла малюнок.

— Він там завжди встигає, — сказала вона. — А сюди ні.
```

Правило:

> **Життєва сцена має доводити канон через біль людини, а не через пояснення героя.**

## 12. Поведінка технологій у побуті

Технологія має бути не головною, а точною.

```yaml
TECH_IN_LIFE_SCENE:
  visible_enough:
    - "HUD дає знак"
    - "екзоскелет блокує мікрорух"
    - "Personal Node пише лог"
    - "піраміда не змінює колір"
    - "капсула показує статус"
    - "сфера вагається"

  not_too_much:
    - "не пояснювати всю архітектуру"
    - "не вставляти довгі технічні блоки без потреби"
    - "не перетворювати сцену на README"
```

  human_gate_present: true

  rune_is_functional: true

## 17. Малий гумор світу

Світ має бути не тільки важкий.

Приклади легших сцен:

```yaml
LIGHT_LIFE_SCENES:
  - "Personal Node блокує третю чашку кави не через здоровʼя, а через angry_email_risk"
  - "дитина вчить дорослого правильно казати ∅✓"
  - "старша жінка свариться зі сферою, бо та надто ввічлива"
  - "пілот провалює дріфт не через страх, а через те, що забув поїсти"
  - "AI Guard пише HOLD, бо герой драматизує звичайний дощ"
```

Фраза:

> **Світ, який уміє тільки страждати, теж стає кристалом.**
