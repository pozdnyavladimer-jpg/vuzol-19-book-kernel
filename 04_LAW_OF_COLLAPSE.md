# 04_LAW_OF_COLLAPSE.md
# Вузол-19 — Law of Collapse: 4D → 3D v0.1

> **4D дає можливість.  
> Людина дає намір.  
> Квітка дає перевірку.  
> Bindu дає дозвіл.  
> 3D отримує дію.**

---

## 1. Головний закон

```text
4D POSSIBILITY
→ HUMAN INTENT
→ BODY SIGNAL
→ SHADOW AUDIT
→ GUARD
→ BINDU
→ 3D ACTION
```

**4D не створює 3D напряму.**  
4D тримає поле можливих форм, а 3D отримує тільки ту форму, яка пройшла через людину, тіло, тінь, Guard і Bindu.

Коротко:

> **Можливість не має права стати реальністю без Human Gate.**

---

## 2. Що таке 4D у романі

У “Вузлі-19” 4D — це не “магічний вимір”, а поле можливостей:

```text
можливі слова
можливі дії
можливі маршрути
можливі світи
можливі майбутні версії людини
можливі форми міста
можливі рішення AI
```

4D — це ще не факт.

Це:

```text
може бути
але ще не має тіла
```

---

## 3. Що таке 3D у романі

3D — це committed reality.

```text
сказане слово
зроблений жест
підключена сфера
запущений код
відкрита капсула
перепрошита піраміда
рани, які зʼявились після дії
памʼять, яка лишилась після вибору
```

3D — це те, що вже має наслідок.

---

## 4. Clean Collapse

Clean Collapse — це правильне схлопування можливості в дію.

```yaml
CLEAN_COLLAPSE:
  possibility: present
  intent: conscious
  body_signal: detected
  shadow_audit: passed
  unknown: preserved_until_needed
  guard: passed
  bindu: action_allowed
  result: 3D_action_with_return_path
```

Руна:

```text
◇✓
ACTION_ALLOWED
```

Фраза:

> **Дія дозволена тоді, коли вона має не тільки напрям, а й право на повернення.**

---

## 5. Dirty Collapse

Dirty Collapse — це заражене схлопування.

```yaml
DIRTY_COLLAPSE:
  possibility: present
  intent: mixed_with_shadow
  body_signal: ignored
  shadow_audit: skipped
  unknown: blocked
  guard: bypassed
  bindu: false_green
  result: 3D_damage_or_prion_loop
```

Руни:

```text
∅╳
⟲△
FALSE_GREEN
```

Фраза:

> **PRION — це можливість, яка отримала тіло раніше, ніж людина встигла зрозуміти, хто в ній цього хотів.**

---

## 6. Чому це важливо в ері наміру

У старому світі між імпульсом і дією була інерція.

```text
думка
→ сумнів
→ час
→ ресурс
→ дія
```

У новому світі інерцію скорочують:

```text
імпульс
→ AI
→ симуляція
→ екзоскелет / сфера / капсула
→ дія
```

Тому головна небезпека майбутнього:

> **світ став достатньо швидким, щоб виконати тінь раніше, ніж людина її усвідомить.**

---

## 7. Закон для AI

AI не має права переводити 4D у 3D напряму.

```yaml
AI_COLLAPSE_RULES:
  forbidden:
    - execute_without_guard
    - fill_unknown_with_fantasy
    - replace_human_gate
    - convert_symbol_to_absolute_truth
    - romanticize_pain
    - present_false_green_as_healing

  required:
    - detect_signal
    - preserve_unknown
    - run_shadow_audit
    - check_human_gate
    - verify_return_path
    - produce_bindu_verdict
```

Коротко:

> **AI може розгорнути варіанти.  
> Але тільки Human Gate вирішує, що має стати дією.**

---

## 8. Закон для сфери Буга

Сфера Буга — це 4D-потенціал тіла.

До підключення вона може бути:

```text
транспортом
зброєю
мостом
тілом
втечею
пасткою
човном
```

Вона стає конкретною 3D-функцією тільки після стану пілота.

```yaml
BUGA_COLLAPSE:
  sphere_status: ready
  operator_status: unknown
  drift_state: pending
  verdict:
    if shadow_drives: "weapon_body"
    if grief_is_seen: "boat_body"
    if control_freezes_unknown: "crystal_body"
```

Фраза:

> **Сфера не була тілом.  
> Вона ставала тим, що в пілоті проходило через неї.**

---

## 9. Закон для пірамід

Піраміда — це великий міський стабілізатор схлопування.

Вона не просто “живить місто”.  
Вона задає такт, за яким імпульси людей, машин і AI стають міськими діями.

```yaml
PYRAMID_COLLAPSE:
  city_signal: collected
  social_pressure: measured
  field_rhythm: stabilized
  guard_schema: applied
  output: city_state
```

Але якщо піраміда заражена PRION:

```yaml
PYRAMID_PRION:
  false_green: high
  unknown: blocked
  pain: suppressed
  human_gate: degraded
  output: hell_crystal
```

Фраза:

> **Коли піраміда бреше, місто не вибухає.  
> Воно стає надто спокійним.**

---

## 10. Закон для ісекай-капсул

Ісекай-капсула — це машина персонального схлопування бажання.

Вона бере 4D-бажання людини:

```text
бути сильним
бути коханим
бути правим
бути святим
бути без болю
бути героєм
```

і швидко дає йому 3D-подібне тіло в симуляції.

Здоровий режим:

```yaml
HEALTHY_ISEKAI:
  pain: seen
  shadow: encountered
  return_to_zero: true
  real_life_change: possible
```

PRION-режим:

```yaml
PRION_ISEKAI:
  pain: converted_to_reward
  shadow: crowned
  return_to_zero: false
  real_life_contact: degraded
```

Фраза:

> **Капсула не лікувала його самотність.  
> Вона дала самотності корону.**

---

## 11. Закон для діалогу

Слово — це теж 4D → 3D.

До вимови існує багато можливих фраз:

```text
вдарити словом
сховатися
пояснити
попросити
промовчати
сказати правду
сказати красиву брехню
```

Коли фраза сказана, вона стає 3D-подією в контакті.

```yaml
SPEECH_COLLAPSE:
  trigger: "критика"
  body_signal: "стиснення руки, затримка дихання"
  shadow_node: "shame"
  phrase_candidate: "Ти нічого не розумієш"
  verdict: "COMMIT_BLOCKED"
```

Руна:

```text
⊙╳
```

Фраза:

> **Іноді найважливіша дія — це слово, яке не отримало тіло.**

---

## 12. Закон для коду

Код — це 4D-логіка, яка хоче стати runtime.

До запуску код — можливість.  
Після запуску — дія в системі.

```yaml
CODE_COLLAPSE:
  idea: "agent loop"
  implementation: "generated code"
  guard_schema: required
  cooldown: required
  decay: required
  memory: required
```

PRION у коді:

```yaml
CODE_PRION:
  looks_clean: true
  executes_fast: true
  guard_missing: true
  loop_risk: high
  false_green: "tests pass but runtime unsafe"
```

Руна:

```text
⟲△
FALSE_GREEN_LOOP
```

Фраза:

> **Код може бути красивим і все одно бути неправильно згорнутим білком.**

---

## 13. Роль Квітки в законі схлопування

Квітка — це не сама дія.  
Квітка — це scan-поле перед дією.

```yaml
FLOWER_COLLAPSE_FUNCTION:
  red_tank: "тілесна ціна / тиск"
  orange_archer: "рух / вектор"
  yellow_engineer: "структура / механіка"
  green_healer: "баланс / return_to_zero"
  blue_guardian: "закон / Human Gate"
  violet_mage: "можливість / майбутній перехід"
  bindu: "verdict"
```

Квітка питає:

```text
Чи має ця можливість право отримати тіло?
```

## 14. Гексаграма як доказ

Гексаграма виникає, коли:

```text
+3 forward
і
-3 backward

зійшлися без брехні
```

Тобто:

```yaml
HEXAGRAM_PROOF:
  violet_future: present
  orange_flow: directed
  yellow_structure: coherent
  blue_law: passed
  green_balance: alive
  red_pressure: endured
  bindu: stable
```

Фраза:

> **Гексаграма не була символом.  
> Вона була доказом, що намір пройшов шість сторін реальності й не збрехав жодній.**

```yaml

    question: "Хто або що хоче цього?"

    question: "Як тіло видало правду раніше за думку?"

    question: "Що блокує або дозволяє?"
  bindu:
    question: "Який verdict?"
  3d_action:
    question: "Що реально сталося або не сталося?"
```
